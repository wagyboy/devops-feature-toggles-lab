# Desk Shop: feature-toggle experiments (DevOps Assignment 10)

A small Flask shop used by a three-person team to test two business hypotheses with feature toggles,
behind GitHub sign-in, deployed on Render, with a DevSecOps pipeline in GitHub Actions.

| Toggle | Hypothesis | Metric |
| --- | --- | --- |
| `quick_buy` | A "Buy now" button on the product list raises the share of visits that end in a purchase | visit conversion = visits with a purchase ÷ visits |
| `stock_badge` | An "Only N left" badge raises clicks on low-stock products | click-through = clicks ÷ impressions of low-stock items |

Each signed-in user is placed in a stable 50/50 bucket per toggle (SHA-256 of flag name + user id).

**Final demo (12/15):** see the [demo plan](docs/demo-plan.md) for the data window, who presents what, and the demo-day checklist.

## Run locally

```bash
docker compose up --build
```

Open <http://localhost:8000> and use **Dev sign-in** (any name; `admin` gets the admin role).
The dev sign-in only exists when `DEV_LOGIN=1`, and the app refuses to start with it on Render.

Tests (both states of every toggle, A&A, CSRF, runtime switching):

```bash
cd app && pip install -r requirements-dev.txt && python -m pytest -v
```

## Layout

| Path | What |
| --- | --- |
| `app/shop/flags.json` | toggle defaults, reviewed in pull requests |
| `app/shop/flags.py` | evaluation: kill switch → force lists → hash bucket |
| `app/shop/auth.py` | GitHub OAuth, roles (`customer`, `admin`), CSRF |
| `app/shop/views.py` | shop pages; server-side check of the `quick_buy` boundary |
| `app/shop/admin.py` | runtime toggle console with audit log, metrics, CSV export |
| `app/shop/metrics.py` | event tracking and per-variant numbers |
| `render.yaml` | Render Blueprint: web service + PostgreSQL, deploys only when checks pass |
| `.github/workflows/devsecops.yml` | lint, tests, Gitleaks, Semgrep, Hadolint, Trivy, ZAP |

## Secrets

No secret is stored in this repository. On Render: `SECRET_KEY` (generated by Render),
`GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET` (entered in the dashboard), `DATABASE_URL` (wired from the database).
Locally: copy `.env.example` to `.env` (git-ignored). Gitleaks scans the full history on every push.
